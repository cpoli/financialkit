# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A quantitative-finance toolkit, conventionally imported as `fk`. It has 14 domain subpackages: `time_value`, `fixed_income`, `options`, `interest_rate_models`, `monte_carlo`, `exotic_options`, `pde_methods`, `stochastic_volatility`, `time_series`, `risk`, `portfolio`, `asset_pricing`, `credit` and `market_microstructure`. They share the SDE integrators, a small constants module and a consistent NumPy-based API. It is educational and research software, not investment advice, and the README and the docs index say so.

financialkit is a structural clone of `../mathematicskit`: same layout, tooling, CI, docs, gallery, history pages, JupyterLite and release flow. Only the domain content differs. When a structural convention seems underspecified, do what mathematicskit does rather than inventing something new. The build plan is `../financialkit-spec.md`, and progress is tracked in `ROADMAP.md`. Domains are built one per session, in the ROADMAP's order.

## Commands

```bash
# setup
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pre-commit install

# lint / format
ruff check .
ruff format .

# unit tests -- everything, or a single subpackage / file / test
MPLBACKEND=Agg pytest -q
pytest financialkit/integrators/tests
pytest financialkit/integrators/tests/test_sde.py::test_gbm_paths_log_moments -q

# the same without the JIT (approximates CI's no-numba job)
NUMBA_DISABLE_JIT=1 MPLBACKEND=Agg pytest -q

# docstring examples (every subpackage's doctests)
MPLBACKEND=Agg pytest --doctest-modules financialkit --ignore-glob="*/tests/*"

# type check (blocking in CI)
mypy financialkit

# docs (re-executes examples/*/plot_*.py via sphinx-gallery -- the only way
# to catch a broken example; do this if you touch docs/ or examples/)
pip install -e ".[docs]"
cd docs && make html
```

CI (`.github/workflows/ci.yml`) runs:

- lint, unit tests, doctests and mypy on Python 3.10-3.15, on Linux, macOS and Windows;
- a minimum-dependencies job on Python 3.10 with numpy, scipy, matplotlib and numba pinned to the floors in `pyproject.toml`;
- a no-numba test job, which also uploads coverage because coverage cannot trace `@njit`-compiled bodies;
- a distribution build and `twine check`.

`.github/workflows/docs.yml` builds the Sphinx site and re-runs every gallery example. `release.yml` publishes to PyPI when a GitHub release is published. `pytest-xdist` is not a test dependency, so run plain `pytest -q`.

Scope stops at a local, green build. Do not create the GitHub repo, push, tag, release, upload to PyPI or mint a DOI; those steps belong to the author.

## Architecture

**One subpackage per finance domain**, at `financialkit/<name>/`, with its tests in `financialkit/<name>/tests/` (there is no top-level `tests/`). Every subpackage has the same internal layout:

- `core/`: ABCs, result dataclasses and any shared `@njit` kernels;
- `systems/`: concrete models, one module per family;
- `utils/`: domain numerics that support `systems/` without being a model;
- `visualizers/`: matplotlib plotting;
- `tests/`.

Do not add or merge domains. A domain may import from domains earlier in the ROADMAP build order but never from later ones, so there are no cycles. Shared pieces have exactly one implementation: for example, Black-76 lives in `options` and `interest_rate_models` calls it; year fractions live in `time_value`.

**numpy/scipy first.** Call `scipy.stats`, `scipy.optimize` (`brentq`, `minimize`, `least_squares`, `linprog`), `scipy.integrate`, `scipy.fft`, `scipy.stats.qmc`, `scipy.linalg` and `scipy.sparse` directly, and wrap them in financialkit's dataclass results, docstrings, visualizers, tests and examples. Hand-write an algorithm only in two cases:

- when no equivalent exists in the allowed dependencies: binomial and trinomial trees, Longstaff-Schwartz, curve bootstrapping, PSOR, the ARMA and GARCH likelihoods, the ADF test with MacKinnon critical values, Ledoit-Wolf shrinkage;
- when the iteration itself is the lesson.

**Dependencies are fixed.** The core dependencies are numpy, scipy and matplotlib, with numba in the `fast` extra. Do not add pandas, statsmodels, scikit-learn, arch, QuantLib or any data-fetching library. Nothing touches the network: not the runtime, not the tests, not the gallery. Accept array-likes through `np.asarray`. Examples use synthetic data from a seeded `np.random.default_rng`. If small bundled CSVs are needed, they go under `financialkit/datasets/`, are generated by a committed script and are added to the package data.

**`financialkit.integrators`** is the shared SDE module. Domains call it and never reimplement path simulation. It provides:

- `euler_maruyama` and `milstein` (diagonal noise);
- exact `gbm_paths` and `ou_paths`;
- `brownian_increments`, `correlated_increments` (Cholesky), `antithetic_increments` and `sobol_increments` (scrambled `qmc.Sobol`, ordered by Brownian bridge), plus `brownian_bridge`;
- `strong_convergence` and `weak_convergence`, which return a `ConvergenceResult`.

Callbacks use the `f(x, t, params)` convention, where `x` is the whole batch of paths with shape `(n_paths, d)`, so the code stays vectorised without numba.

- A scalar `x0` returns paths of shape `(n_paths, n_steps + 1)`; a vector `x0` returns `(n_paths, n_steps + 1, d)`.
- Every scheme accepts a precomputed `dW`, so antithetic, Sobol and correlated noise work with any scheme, and schemes can be compared on common random numbers.

**Numba is optional.** Import `njit` from `financialkit._jit` (re-exported as `financialkit.integrators.njit`), never from `numba` directly. Without numba it is a no-op decorator, which is what makes Pyodide and JupyterLite work.

- Only genuinely hot inner loops get `@njit`: the SDE kernels, trees, PDE time-stepping and path-dependent Monte Carlo. Most domains have no `@njit` code; don't add it speculatively.
- Callbacks handed to a compiled kernel must themselves be `@njit` dispatchers, never bound methods.
- PDE grid spacing, coefficients and boundary data go through the `params` array, as in mathematicskit's `pde`, so one compiled kernel serves every grid.
- Do not use `cache=True`.
- A test that is only practical with the JIT is gated with `@pytest.mark.skipif(not HAS_NUMBA, ...)`.

**`financialkit.constants`** stays small. It holds:

- `TRADING_DAYS_PER_YEAR` and `CALENDAR_DAYS_PER_YEAR`;
- the `DayCount` enum (`ACT_360`, `ACT_365F`, `THIRTY_360_US`, `THIRTY_E_360`, `ACT_ACT_ISDA`);
- `DEFAULT_ATOL`, `DEFAULT_RTOL` and `DEFAULT_MAX_ITER`, so "did this converge" means the same thing everywhere.

It holds no currency or market data, and the day-count arithmetic itself lives in `time_value`.

**Shared base classes** follow one flow. `core/base.py` defines abstract classes and a small `@dataclass` result per model family; these are never bare tuples, so visualizers have a stable interface. Concrete models in `systems/` implement those classes, and `visualizers/` plots the result dataclasses. Read the target subpackage's `__init__.py` and `core/base.py` before assuming more.

## Conventions

**Finance conventions apply package-wide:**

- Time is in years.
- Rates, volatilities and yields are decimals (`0.05`, not `5`).
- Rates are continuously compounded unless a parameter says otherwise.
- Dividends are a continuous yield `q`, defaulting to `0.0`.
- `option_type` is `"call"` or `"put"`.
- Closed-form pricers and Greeks broadcast over array inputs, so a smile or surface is one call.

**Randomness:**

- Every stochastic function takes `rng: np.random.Generator | int | None = None` and normalises it with `np.random.default_rng(rng)`.
- Random numbers are drawn in Python and passed into kernels as arrays. Kernels never call `np.random`, so results are identical with and without numba.

**Tests:**

- Deterministic results use `DEFAULT_ATOL`/`DEFAULT_RTOL`, or a tolerance justified in a comment.
- Monte Carlo tests are seeded and assert agreement within a few standard errors (for example `abs(est - exact) < 4 * se`), never a bare fixed tolerance.
- Prefer closed forms, parity relations and published values. For published values, use Hull, *Options, Futures, and Other Derivatives*, Haug, *The Complete Guide to Option Pricing Formulas*, or the original paper, and cite the table or example number in the test docstring.
- A visualizer needs only a smoke test.
- Every `@njit` kernel must also pass with numba absent.

**Code style:**

- Single-letter math names (`S`, `K`, `T`, `r`, `q`, `n`, `x`, ...) are intentional. See the deliberate `ruff` ignores in `pyproject.toml` (`E741` and others) rather than "fixing" them.
- Every public function and class needs a NumPy-style docstring with `Parameters`, `Returns` and, where it adds value, an `Examples` section with a runnable doctest. Doctests run in CI.
- Every model cites its source, either a textbook edition or a paper.
- `mypy financialkit` is clean and blocking in CI, so keep it that way. Unannotated bodies are skipped because `check_untyped_defs = false`.

**Rules for each domain:**

- `docs/source/history/<domain>_breakthroughs.rst` needs at least 15 dated breakthroughs, formatted like mathematicskit's linalg page, each with an `*Implementation:*` line. Plan them in `ROADMAP.md` before writing the domain, and make `systems/` implement every one.
- Each breakthrough links its own gallery example or examples via `.. minigallery::`, and no example is linked from two breakthroughs. Each example's title and content must show that breakthrough's subject. Split combined examples into focused ones, and when the match is unclear, change the example rather than the breakthrough.
- Gallery scripts live at `examples/<domain>/<topic>/plot_NN_<slug>.py`. They are in sphinx-gallery format (an RST docstring and `# %%` cells), self-contained and seeded, and each must run in under 5 seconds without numba, so size path counts and grids accordingly.
- Register each new domain in `conf.py`'s `SUBPACKAGES` under its `_CATEGORY_ORDER` category: Foundations, Derivatives, Numerical Methods, Rates & Credit, Portfolios & Asset Pricing, or Risk & Markets.
